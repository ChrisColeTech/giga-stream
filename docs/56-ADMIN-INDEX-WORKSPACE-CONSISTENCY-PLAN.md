# 56 - The admin indexes, workspaces and job forms use one action grammar (plan v1)

**Status: v1 (2026-10-19).** Owner: "the index promote actions are not correct. some of the indexes toolbars are still
pointing to a wrong page and are missing the preview action"; "the playlist still has its sync now action in the table
toolbar instead of promote action, and playlist form is mising the input for name"; "on the workspace, the playlist
has the wrong promote action and missing sync"; "jobs table still has stop in the table toolbar"; "the new job form
should not have totally different fields than the edit job form"; "on the job form it only shows options for movies
and series, missing the option for all or both"; "on the workspace some of the dropdowns are not populating with the
same options as on the index". Amends `43`, `55` and the current Jobs contract. Scope: the admin app and the backend's
playlist-import and catalog-job contracts. Landing (`07` 6.1): backend contract first, then one admin wave.

## 1. Why (observed in the merged code)

- The index promotes are mixed grammar: Channels `Preview ->` and Jobs `Run job` act on ticks; Providers `Titles ->`,
  Titles `Jobs ->` and Playlists `Jobs ->` are unconditional tab hops. Provider/Title preview windows now exist, so
  those hops are stale (`INDEX_FRAMES`, `useForwardVerbs`).
- Playlists `Sync now` lives in the `TableStrip` (`PLAYLIST_BULK_ORDER` = Sync now, Enable, Disable, Delete), acts on
  the ticked set through the generated jobs, and incorrectly refuses a disabled JOB even though a manual job run only
  requires the PLAYLIST enabled. The Playlist workspace promotes `Channels ->` and has no Sync action.
- `NewPlaylistForm` asks only File/Web address and the address/file. The backend already accepts an optional name for a
  URL and derives one when absent; multipart accepts no ordinary fields, so adding Name for file imports needs a small
  contract change. The workspace edits Name after import - the index form and edit form do not describe the same
  record identity.
- Jobs `Stop` remains on the table strip although the statusbar's Stop stops every running job. NewJobForm uses only
  Name + Scope/Kind; edit also has Enabled, Pages and Schedule. Both render the same Scope/Kind component, but the
  create form omits the rest. Kind is only `movie | tv`; omitted Kind silently defaults to Movies - there is no All.
- Discover shows a Pages field even though sliced Discover walks every slice, and can retain a stale Kind after scope
  changes. These are real config inconsistencies, not option-population failures.

## 2. Decisions

1. **The index promote table:** Channels `Preview` (unchanged behavior, arrow removed); Providers `Preview` (exactly one ticked,
   previewable embed provider); Titles `Preview` (exactly one ticked title with a previewable source/TMDB id);
   Playlists `Sync now` (the ticked set); Jobs `Run job` (the ticked set, unchanged); Accounts none. Providers/Titles
   lose their page hops; the row eyes remain.
2. **Playlist Sync moves out of the strip.** `sync` leaves `PLAYLIST_BULK_ORDER`; `Sync now` in the index promote uses
   the same bulk runner and ticked set. Its gate: a row ticked, playlist enabled, generated job present, job not running,
   backend reachable, no bulk work. A disabled JOB does NOT block a manual sync. The strip keeps Enable, Disable,
   Delete.
3. **Playlist workspace promotes `Sync now`.** It runs that playlist's generated job with the same corrected gate.
   `Channels ->` is removed as the promote (the Channels list still filters by playlist through its own Playlist
   query; no second toolbar verb is invented).
4. **Name returns to New playlist, first.** Name is required by the admin form for File and Web imports; the URL body
   sends `{ name, url }`; multipart accepts one ordinary `name` field plus the file. The backend keeps name optional for
   external/legacy clients and retains derived-name fallback, but the admin never submits an unnamed import.
5. **The statusbar is the one Stop.** `stop` leaves the Jobs `TableStrip`; it keeps Enable, Disable, Delete. The
   statusbar's Stop remains the emergency stop for every running job. No workspace or table owns another Stop.
6. **New and edit catalog jobs share one field grammar and option source.** Both render Name, Scope, Kind (when the
   scope uses it), Pages (only when operationally meaningful), Enabled and Schedule from the same components and
   constants. Type stays implicit/read-only Catalog (playlist jobs are generated by imports and cannot be created
   here). Edit keeps Last run as its read-only group.
7. **Kind gains explicit `All` (`"all"`) in a Select.** Options, in order: All, Movies, Series. Existing `movie`/`tv` jobs keep
   their values. New jobs default to All. Trending/Popular with All runs both TMDB paths; progress/counts combine both
   deterministically. Discover/Recent already run both and hide Kind. Omitted legacy Kind keeps its historical Movies
   meaning; it is never silently reinterpreted as All.
8. **Pages and stale config corrected.** Pages renders only for Trending/Popular (where the runner consumes it), not
   Discover/Recent. Moving to either both-kind scope removes Kind from stored config; moving back requires/sets the
   explicit current Kind. New/edit round-trip the same schedule options (`Off`, presets, Custom) and the same values.
9. **One option source per domain field.** Scope (4 choices) and Kind (All/Movies/Series) are native Selects under the
   `01` choice grammar; New and edit import the same option arrays and visibility functions; tests
   compare both rendered sets. A copied option list in a form or workspace is prohibited.
10. **The nav pill owns navigation.** No index or workspace toolbar changes tabs. `Titles ->`, `Jobs ->` and
    `Channels ->` are deleted, not relocated. A promote is an operation on the current record/ticked set (`Preview`,
    `Sync now`, `Run job`) or the slot is empty. The promote words carry no navigation arrow. The obsolete
    `ForwardButton`/`ForwardDestination` vocabulary is deleted once its final consumer is gone.

## 3. Changes from what is merged

- `src/backend`: playlist multipart schema/route accepts Name; catalog-job schemas/config gain Kind `all`; title-walk
  runs both paths and combines progress/counts; config normalization drops Kind/Pages for scopes that ignore them;
  backend tests for imports, jobs and Trending/Popular All.
- `src/admin`: `INDEX_FRAMES`/`useForwardVerbs` (renamed/reduced to operational promotes), the obsolete
  `ForwardButton`/`ForwardDestination` removed, and the Provider/Title preview gates; playlist bulk/promote/workspace
  sync wiring and NewPlaylistForm draft/body; Jobs bulk strip, NewJobForm/JobDetails/JobSchedule shared field
  composition, job schema/draft/body/copy and option constants.
- Existing tests named by the audit: `toolbar-verbs`, provider/title/playlist/jobs markup, playlist-bulk/flows/service,
  job-bulk/run-gate/schedule/service, and backend playlist-import/jobs/title-walk suites.
